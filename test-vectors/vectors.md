# QuinLED Ultra protocol v2: test vectors

Generated by `gen_vectors.c` from `include/ultra_protocol.h`. Do not edit by hand: change the generator and run it again.
Bytes are hex, in wire order: MSB of byte 0 first. Multi-byte fields are big-endian. An implementation that builds the same inputs must produce exactly these bytes.

## 1. CRC check values

The standard check string `123456789` (ASCII):

| CRC | Parameters | Result |
|---|---|---|
| CRC-8/SMBus (header) | poly 0x07, init 0x00, no reflection, no final XOR | `0xF4` |
| CRC-16/CCITT-FALSE (slots) | poly 0x1021, init 0xFFFF, no reflection, no final XOR | `0x29B1` |

## 2. Headers

MAGIC `5A D2`, VERSION << 4 | FLAGS, TIME (4, big-endian), CRC-8 over the first 7 bytes.

### `hdr_normal`: a normal header

TIME 0x00ABCDEF, FLAGS 0.

A v2 board **accepts** this header.

```
5A D2 20 00 AB CD EF D4
```

### `hdr_time_zero`: TIME 0

TIME is the host's microsecond clock, low 32 bits; 0 is valid.

A v2 board **accepts** this header.

```
5A D2 20 00 00 00 00 F7
```

### `hdr_time_max`: TIME 0xFFFFFFFF

The clock wraps every 71.6 minutes; boards handle the wrap.

A v2 board **accepts** this header.

```
5A D2 20 FF FF FF FF 29
```

### `hdr_flag_hint`: FLAGS 0x02 (HINT, reserved)

A valid header. A board that doesn't know a hint processes the frame as usual. Hosts send FLAGS 0 until a hint is defined.

A v2 board **accepts** this header.

```
5A D2 22 00 AB CD EF 10
```

### `hdr_flag_rw`: FLAGS 0x01 (RW, reserved for the return channel)

A valid header. Today's boards take the clock sync but ignore every slot of the frame and keep their lock. Hosts must not send it yet.

A v2 board **accepts** this header.

```
5A D2 21 00 AB CD EF B6
```

### `hdr_bad_crc`: one TIME bit flipped, CRC not updated

Same as hdr_normal with the last TIME bit flipped: the CRC-8 no longer matches.

A v2 board **rejects** this header.

```
5A D2 20 00 AB CD EE D4
```

### `hdr_version1`: version 1 with a correct CRC

Protocol v1 (header first, withdrawn). The CRC is correct, but a v2 board rejects every frame of another version: no lock, no clock sync, no slot.

A v2 board **rejects** this header.

```
5A D2 10 00 AB CD EF 82
```

### `hdr_bad_magic`: wrong magic with a correct CRC

MAGIC 0x5BD2 instead of 0x5AD2.

A v2 board **rejects** this header.

```
5B D2 20 00 AB CD EF 0B
```

## 5. Switching boards forced to WS2805 / WS2915: the WS config-frame sequence for 2 boards

10 frames, sent with the same WS bit timing and a reset gap after each. Frames 0-3: WS2805 format (5 bytes per board = the message `D2 A5 01 03 CRC`), frame 4: WS2805 all zero; frames 5-8: WS2915 format (header `FF FF FF 80`, then per board the message and its complement), frame 9: WS2915 all zero. Consecutive frames differ in length by 1 byte of zero padding. Afterwards the host sends the start-up preamble and everything again.

| Frame | Bytes | Hex |
|---|---|---|
| 0 | 11 | `D2 A5 01 03 75 D2 A5 01 03 75 00` |
| 1 | 12 | `D2 A5 01 03 75 D2 A5 01 03 75 00 00` |
| 2 | 11 | `D2 A5 01 03 75 D2 A5 01 03 75 00` |
| 3 | 12 | `D2 A5 01 03 75 D2 A5 01 03 75 00 00` |
| 4 | 11 | `00 00 00 00 00 00 00 00 00 00 00` |
| 5 | 26 | `FF FF FF 80 D2 A5 01 03 75 2D 5A FE FC 8A D2 A5 01 03 75 2D 5A FE FC 8A 00 00` |
| 6 | 25 | `FF FF FF 80 D2 A5 01 03 75 2D 5A FE FC 8A D2 A5 01 03 75 2D 5A FE FC 8A 00` |
| 7 | 26 | `FF FF FF 80 D2 A5 01 03 75 2D 5A FE FC 8A D2 A5 01 03 75 2D 5A FE FC 8A 00 00` |
| 8 | 25 | `FF FF FF 80 D2 A5 01 03 75 2D 5A FE FC 8A D2 A5 01 03 75 2D 5A FE FC 8A 00` |
| 9 | 26 | `FF FF FF 80 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00` |

The message: MAGIC `D2 A5`, CMD `01` (protocol), ARG `03` (Ultra), CRC-8/SMBus over those 4 bytes = `75`.
